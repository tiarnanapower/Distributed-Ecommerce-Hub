# Local setup guide

## Requirements

- **Node 20.9 or later.** Check with `node -v`.
- Nothing else. No Docker, no Redis, no external database, no API keys, no paid services.

## First run

```bash
npm install
npm run db:setup
npm run dev
```

Open <http://localhost:3000> and press **Sign in locally**.

### What `db:setup` does

1. **`node scripts/setup-env.mjs`** — creates `.env` from `.env.example` if it does not exist, and generates
   an `ENCRYPTION_KEY` and `SESSION_SECRET`. Re-running it never overwrites an existing `.env`; it only fills
   blank secrets.
2. **`prisma generate`** — builds the typed Prisma client.
3. **`prisma migrate deploy`** — applies the committed migrations to `prisma/dev.db`.
4. **`npm run db:seed`** — creates the demo organisation.

It is safe to run repeatedly.

## What gets seeded

| | |
| --- | --- |
| Organisation | Acme Global Commerce |
| Companies | Acme Consumer (B2C), Acme Wholesale (B2B), Acme Outlet |
| Regions | Nine, across the three companies |
| Brands | Acme Home, Acme Field, Acme Studio |
| Stores | Twelve, in ten currencies including JPY (zero-decimal) |
| Storefront channels | Fifteen, including one Multi-Storefront parent with three |
| Health | Eight healthy, three warning, one critical with an invalid token |
| Products | ~270 snapshots with deliberate gaps, overrides and drift |
| Orders | ~790 with line items and timelines |
| Customers | ~215, masked, store-scoped |
| Conflicts | ~50, generated by the real comparison engine |
| Plus | Themes, content, promotions, jobs, deployments, approvals, audit events, notifications |

Everything is fictional. No real merchant, customer or transaction data appears anywhere. Emails use the
reserved `.example` domain and can never route mail. See [Demo mode](demo-mode.md).

The seed is deterministic — a fixed PRNG seed — so every machine gets the same estate.

## Everyday commands

```bash
npm run dev                    # development server
npm run verify                 # typecheck + lint + unit tests
npm run test                   # unit tests only
npm run test:e2e               # end-to-end tests (installs a browser on first use)
npm run db:studio              # browse the database
npm run db:reset               # wipe and re-seed
node scripts/smoke-routes.mjs  # request every route with a real session
```

### The route smoke test

`scripts/smoke-routes.mjs` mints a session directly in the database, then requests all 60 routes and prints
the status of each. It catches server-render failures that a type check cannot — bad Prisma queries, missing
props, and server/client boundary mistakes. Run it with the dev server up:

```bash
npm run dev
node scripts/smoke-routes.mjs http://127.0.0.1:3000
```

## Troubleshooting

### `Invalid environment configuration`

A required variable is missing or malformed. Regenerate the file:

```bash
rm .env && npm run db:setup
```

### `ENCRYPTION_KEY must decode to exactly 32 bytes`

The key is not valid 32-byte base64. Generate a new one:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

Paste it into `.env` as `ENCRYPTION_KEY`. Any credential encrypted with the old key becomes unreadable —
which the UI reports honestly rather than failing silently.

### `No local administrator exists yet` on the login page

The database is reachable but unseeded:

```bash
npm run db:seed
```

### `Table main.X does not exist`

Migrations have not been applied:

```bash
npx prisma migrate deploy
```

### A page 500s after editing a client component

Almost always a **server/client boundary** mistake: a `'use client'` component importing a *value* (not just a
type) from a module that touches Prisma. That drags the database client into the browser bundle and every page
below the shell fails with `Reading from "node:crypto" is not handled`.

Fix it by extracting the shared constant into a dependency-free module under `src/lib/` — as
`src/lib/date-range.ts` and `src/lib/search-types.ts` do. `type`-only imports are erased at compile time and
are always safe.

### Port 3000 is in use

```bash
npm run dev -- --port 3100
```

### Playwright cannot find a browser

```bash
npx playwright install chromium
```

### Starting completely fresh

```bash
rm -f prisma/dev.db prisma/dev.db-journal .env
npm run db:setup
```
